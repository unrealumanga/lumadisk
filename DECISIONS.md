# Decisions

## P0.2 measurement harness

- No new dependencies. Peak RSS on Windows uses std-only FFI to `K32GetProcessMemoryInfo`
  (kernel32, `PeakWorkingSetSize`); on Linux it reads `VmHWM` from `/proc/self/status`.
  `windows-sys` was rejected because one function and one struct do not justify a crate.
- `src/lib.rs` re-exports `model`, `scanner`, `treemap` so `benches/scan.rs` calls the real code.
  `main.rs` still declares its own modules, so the app build is unchanged. Side effect: unit tests
  in those modules now run twice (lib target and bin target).
- `scanner::find_duplicate_groups` was made `pub` (visibility only, no behaviour change) so the
  dup-finder can be timed in isolation.
- The tree generator lives in `tools/treegen.rs`, used by `examples/gen_tree.rs`. Trees are
  written to a directory the caller chooses (use a temp dir); nothing is committed.

## Orchestration (brief addendum §7/§8, adopted 2026-10-22)
- **Layer 1:** `orchestration/events.jsonl` (append-only) -> `STATE.md` generated by `orchestration/render_state.py` (python stdlib; jq not installed here). STATE.md is no longer hand-edited.
- **Layer 2 tool: workmux (provisional).** tmux-native, matches psmux; per-agent worktrees via `--foreach`. Not installed yet. Revisit if: it fails to run under psmux on Windows -> fall back to raw psmux + `git worktree`. Skip-permission flags scoped to worktrees; no web dashboard beyond 127.0.0.1.
- **Debate caveat:** the Agent tool only reaches Claude models, so a "cross-model" debate through it has correlated blind spots (7.5). Real debates should use codex and Gemini CLI as one side or both.

### Priors for pre-identified debates (written BEFORE any Round 1, per 7.4)
- D1 MFT: no for default; at most an opt-in later. Elevation and AV risk outweigh speed, and FindFirstFileExW is likely fast enough (measure first).
- D2 default size: physical ("what deleting returns"), with logical one click away and both always shown in the detail panel.
- D3 handoff: arc-swap of an immutable snapshot, plus a cancel token checked per directory read.
- D4 treemap: aggregate by directory first, then by pixel area; cap ~ visible-tile budget, not file count.
- D5 Windows artifact: signed portable .exe primary, installer secondary (cost vs. SmartScreen unknown).
- D6 HSM vendor: no prior; needs UAE availability research.
- D7 Linux: AppImage primary, .deb secondary.
- Order of need: D2 (WS2a, now), D3 and D4 (WS3), D1/D5-D7 later. Debates run so far: 0 of 3 this session.
